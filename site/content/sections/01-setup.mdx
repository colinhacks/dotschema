## Setup

Install dotschema, then add it to TypeScript and to each tool that loads your code.

### Install

You'll need:

- **TypeScript 7.1 (currently in beta).** The first release with content mappers.
- **Node 24 or later.**

```sh
npm install -D dotschema typescript@beta
```

If your app runs under the preload, not as a bundle, dotschema builds each schema's module at run time, so install it as a dependency:

```sh
npm install dotschema
npm install -D typescript@beta
```

### TypeScript

Add dotschema to `tsconfig.json` as a content mapper:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [ // [!code ++]
    { "package": "dotschema", "extensions": [".schema.jsonc"] } // [!code ++]
  ] // [!code ++]
}
```

Then type-check with `--runExternalCode`, which lets `tsc` run content mappers:

```jsonc title="package.json"
{
  "scripts": {
    "typecheck": "tsc --noEmit --runExternalCode" // [!code ++]
  }
}
```

### Plugins

Install the plugin for your runtime or framework of choice:

<Tabs items={["Node", "Bun", "Nub", "Vite", "Next.js", "esbuild", "webpack", "Rspack", "Cloudflare", "Jest"]}>
<Tab value="Node" id="setup-node">

Load dotschema's preload with `--import`, which turns each schema file into a module as it loads:

```sh
node --import dotschema/register main.ts
```

</Tab>
<Tab value="Bun" id="setup-bun">

Add the preload to `bunfig.toml`, and under `[test]` for `bun test`:

```toml title="bunfig.toml"
preload = ["dotschema/register"]

[test]
preload = ["dotschema/register"]
```

For Bun's bundler, use the esbuild plugin:

```ts title="build.ts"
import dotschema from "dotschema/esbuild";

await Bun.build({
  entrypoints: ["main.ts"],
  target: "bun",
  plugins: [dotschema()],
  outdir: "dist",
});
```

</Tab>
<Tab value="Nub" id="setup-nub">

Add the preload to `nub.jsonc`, for `nub main.ts` and `nub --test`:

```jsonc title="nub.jsonc"
{
  "preload": ["dotschema/register"]
}
```

</Tab>
<Tab value="Vite" id="setup-vite">

Add the plugin to your Vite config, which builds each schema's module in the dev server and in the build, for the browser and for the server:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import dotschema from "dotschema/vite";

export default defineConfig({
  plugins: [dotschema()],
});
```

For Vitest, this plugin is all you need. Rollup and Rolldown take it too:

```js title="rollup.config.mjs"
import dotschema from "dotschema/vite";

export default {
  input: "main.js",
  plugins: [dotschema()],
  output: { file: "dist/main.mjs", format: "es" },
};
```

</Tab>
<Tab value="Next.js" id="setup-nextjs">

Wrap your Next.js config with `withDotschema`:

```ts title="next.config.ts"
import type { NextConfig } from "next";
import { withDotschema } from "dotschema/next";

const nextConfig: NextConfig = {
  // ...
};

export default withDotschema(nextConfig);
```

Your server and client components can now import schemas, with Turbopack or webpack, and `next build` fails on a type error.

To type-check without building, run `next typegen` first, which writes the route types:

```json title="package.json"
{
  "scripts": {
    "typecheck": "next typegen && tsc --noEmit --runExternalCode"
  }
}
```

<Details summary="How the build checks the types" id="nextjs-type-check">

Next.js type-checks without `--runExternalCode`, so `withDotschema` turns that check off and runs `tsc --noEmit --runExternalCode` inside `next build` in its place.

</Details>

<Details summary="Beside Motherload or Reylo" id="nextjs-wrappers">

Beside Motherload's `withMotherload` or Reylo's `withReylo`, the wrappers nest in either order:

```ts title="next.config.ts"
export default withMotherload(withDotschema(nextConfig));
```

</Details>

</Tab>
<Tab value="esbuild" id="setup-esbuild">

Add the esbuild plugin, which builds each schema's module at build time, so a bundled app needs no preload:

```js title="build.mjs"
import * as esbuild from "esbuild";
import dotschema from "dotschema/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  platform: "node",
  format: "esm",
  plugins: [dotschema()],
  outfile: "dist/main.mjs",
});
```

</Tab>
<Tab value="webpack" id="setup-webpack">

Load schema files with dotschema's loader:

```js title="webpack.config.mjs"
export default {
  // ...
  module: {
    rules: [
      { test: /\.schema\.(jsonc|json5)$/, use: "dotschema/webpack" },
    ],
  },
};
```

</Tab>
<Tab value="Rspack" id="setup-rspack">

Load schema files with dotschema's loader:

```js title="rspack.config.mjs"
export default {
  // ...
  module: {
    rules: [
      { test: /\.schema\.(jsonc|json5)$/, use: "dotschema/webpack" },
    ],
  },
};
```

</Tab>
<Tab value="Cloudflare" id="setup-cloudflare-workers">

Add dotschema's Vite plugin beside Cloudflare's:

```ts title="vite.config.ts"
import { cloudflare } from "@cloudflare/vite-plugin";
import { defineConfig } from "vite";
import dotschema from "dotschema/vite";

export default defineConfig({
  plugins: [dotschema(), cloudflare()],
});
```

Deploy with `wrangler deploy` after `vite build`: Wrangler's own bundler takes no plugin.

</Tab>
<Tab value="Jest" id="setup-jest">

Add dotschema's transformer to your Jest config:

```js title="jest.config.js"
export default {
  transform: { "\\.schema\\.(jsonc|json5)$": "dotschema/jest" },
  extensionsToTreatAsEsm: [".jsonc", ".json5"],
};
```

```sh
# Jest runs ES modules only behind this Node flag
NODE_OPTIONS=--experimental-vm-modules npx jest
```

<Details summary="Beside another transformer for .jsonc" id="jest-transformers">

Jest runs the first pattern that matches a file, so beside another transformer for `.jsonc` or `.json5`, such as Motherload's, dotschema's pattern comes first:

```js title="jest.config.js"
export default {
  transform: {
    "\\.schema\\.(jsonc|json5)$": "dotschema/jest",
    "\\.(jsonc|json5)$": "motherload/jest",
  },
};
```

</Details>

</Tab>

### Editors

Set up your editor to use the TypeScript 7.1 language server, with content mappers on.

<Tabs items={["VS Code", "Cursor", "Zed"]}>
<Tab value="VS Code" id="editor-vscode">

1. Install the **TypeScript 7** extension (`TypeScriptTeam.native-preview`).
2. Point it at the project's TypeScript: the extension's own copy is TypeScript 7.0, which has no content mappers.

   ```json title=".vscode/settings.json"
   {
     "js/ts.experimental.useTsgo": true,
     "js/ts.tsdk.path": "./node_modules/typescript"
   }
   ```

3. Trust the workspace, and click **Allow** when the extension asks to use the workspace's TypeScript. Content mappers run in a trusted workspace only.

</Tab>
<Tab value="Cursor" id="editor-cursor">

1. Install the **TypeScript 7** extension (`TypeScriptTeam.native-preview`).
2. Point it at the project's TypeScript: the extension's own copy is TypeScript 7.0, which has no content mappers.

   ```json title=".vscode/settings.json"
   {
     "js/ts.experimental.useTsgo": true,
     "js/ts.tsdk.path": "./node_modules/typescript"
   }
   ```

3. Trust the workspace, and click **Allow** when the extension asks to use the workspace's TypeScript. Content mappers run in a trusted workspace only.

</Tab>
<Tab value="Zed" id="editor-zed">

1. Install the **TypeScript Language Server** extension by Zed Industries (search for "tsgo").
2. Point it at the project's TypeScript, with content mappers on:

   ```jsonc title=".zed/settings.json"
   {
     "languages": {
       "TypeScript": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       },
       "TSX": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       }
     },
     "lsp": {
       "typescript-ls": {
         // the extension's own download is TypeScript 7.0, which has no content mappers
         "binary": {
           "path": "node_modules/typescript/bin/tsc",
           "arguments": ["--lsp", "--stdio"]
         },
         "initialization_options": { "runExternalCode": true }
       }
     }
   }
   ```

3. Trust the folder.

Zed doesn't send schema files to the language server, so an error inside one shows only in the type check.

</Tab>
</Tabs>
