## FAQ

<Accordions>
<Accordion title="Can a schema file hold comments?" id="faq-comments">

Yes. A schema file is JSONC, so it can hold comments and trailing commas:

```jsonc title="user.schema.jsonc"
{
  // who can sign in
  "type": "object",
  "properties": {
    "name": { "type": "string", "minLength": 1 },
    "role": { "enum": ["admin", "member"] },
  },
  "required": ["name"],
  "additionalProperties": false,
}
```

</Accordion>
<Accordion title="Which drafts does dotschema read?" id="faq-drafts">

Draft-06, draft-07, 2019-09 and 2020-12. The [`$schema` keyword](#drafts) picks one, and a schema without it is draft-07. A draft-04 or older schema is an error at the type check.

</Accordion>
<Accordion title="How much does dotschema add to a bundle?" id="faq-bundle">

Its validator, once, and a module for each schema that holds the schema. The opening example's `main.ts`, bundled and minified by esbuild, with dotschema's files counted together:

```text title="esbuild's analysis" bundle="main.ts"
  dist/main.mjs         71.1kb  100.0%
   ├ dotschema          70.6kb   99.3%
   ├ user.schema.jsonc   460b     0.6%
   └ main.ts              38b     0.1%
```

With [`"validators": "interpret"`](#validators), the bundle leaves out the code that compiles each validator:

```text title="esbuild's analysis" bundle="main.ts" validators="interpret"
  dist/main.mjs         49.6kb  100.0%
   ├ dotschema          49.1kb   99.0%
   ├ user.schema.jsonc   460b     0.9%
   └ main.ts              38b     0.1%
```

A bundle carries the code of only the formats its schemas use, and esbuild leaves out a definition nothing imports.

</Accordion>
<Accordion title="What isn't supported?" id="faq-limits">

Each of these is an error at the type check:

| Refused | Instead |
| --- | --- |
| A `$ref` to a URL (`https:`, `urn:`) | Save the schema as a `.schema.jsonc` file in the project, and `$ref` the file |
| A draft-04 or draft-03 schema | Declare draft-06 or a later draft in `$schema` |

</Accordion>
